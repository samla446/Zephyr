# Zephyr 智能节点 + Linux 上位机 UART 通信系统

基于 STM32H563ZI（Cortex-M33）与 Zephyr RTOS 的工业数据采集节点，
通过串口与 PC 上位机通信，实现「采集 → 时间戳 → 校验 → 落盘」的完整链路。
另扩展 CAN 总线，与 STM32F103 裸机节点（标准库）组成双节点双向收发。

## 功能特性

- **四线程架构**：UART 接收、LED 控制、传感器采集、按键输入互相解耦，
  通过消息队列通信，避免共享可变状态
- **中断驱动串口接收**：`uart_irq_callback` + 消息队列，避免轮询导致的 overrun 丢字节
- **自定义文本协议**：帧内校验和、帧序号、`OK:` / `ERR:` 指令回执
- **RTC 时间戳**：片内 RTC + LSE，每帧数据自带精确时间
- **参数持久化**：Zephyr NVS（Log-structured）+ 魔数 + 格式版本号校验，上电自动加载
- **看门狗保护**：IWDG + 多线程心跳监督，任一线程失联则停止喂狗，硬件自动复位
- **复位原因识别**：区分上电 / 复位按钮 / 看门狗复位
- **CAN 双节点**：H563（FDCAN）↔ F103（bxCAN）真实总线双向收发，采样点对齐
- **上位机**：pyserial 双线程、校验和验证、丢帧检测、ACK 超时告警、CSV 落盘

### CAN 双节点拓扑

```
┌─────────────────┐              ┌─────────────────┐
│  H563 (Zephyr)  │              │  F103 (裸机)     │
│  FDCAN1         │              │  CAN1 (bxCAN)    │
│  PD1=TX  PD0=RX │              │  PA12=TX PA11=RX │
└───┬─────────┬───┘              └───┬─────────┬───┘
    │SN65HVD230│                     │SN65HVD230│
    └────┬─────┴──── CANH ───────────┴────┬─────┘
         └─────────────── CANL ───────────┘
              （两端各 120Ω 终端电阻）

   0x123（2s 周期）──────►  F103 收
   H563 收 ◄────── 0x101（1s 周期）
```

## 通信协议

### 上行：数据帧（UART）

```
$S,<seq>,<YYYY-MM-DD HH:MM:SS>,<温度>,<湿度>*<校验和>
```

示例：

```
$S,17,2026-10-15 12:00:36,21.7,41.7*A8
```

| 字段 | 说明 |
|------|------|
| `seq` | 帧序号，从 0 递增，上位机据此检测丢帧 |
| 时间戳 | 来自片上 RTC |
| 温度 / 湿度 | 定点数，单位 0.1（`21.7` 内部是 217） |
| 校验和 | `$` 之后到 `*` 之前所有字符的字节和，取低 8 位，两位十六进制 |

### 下行：控制指令

| 指令 | 作用 |
|------|------|
| `on` / `off` | LED 常亮 / 常灭 |
| `blink <ms>` | LED 闪烁，周期 1~10000 ms |
| `status` | 查询 LED 状态与最新传感器数据 |
| `start` / `stop` / `toggle` | 开始 / 停止 / 切换数据采集 |
| `save` / `read` | 保存 / 读取 Flash 中的配置 |
| `crash` | 人为制造线程卡死，用于验证看门狗（演示用） |

所有指令均有回执：成功打印 `OK:<内容>`，失败打印 `ERR:<原因>`。

### CAN 帧（双节点互通）

经典 CAN 固定 8 字节，靠 11 位标准帧 ID 区分来源：

- **H563 → F103**：ID `0x123`，DLC 8，`[0]`=计数(0~255 循环)、`[1]`=0xAA、`[2]`=0x55、其余 0，周期 2 s
- **F103 → H563**：ID `0x101`，DLC 4，`[0..1]`=计数低/高字节、`[2]`=0xAA、`[3]`=0x55，周期 1 s

- 波特率 125 kbit/s，采样点 87.5%（两侧对齐，见 `MyCAN.c` 注释）
- H563 过滤器 `mask=0` = 不关心任何位 = 全收；F103 用 32 位屏蔽位模式且屏蔽位全 0 = 全收
- 目前载荷是固定测试图案，尚未接入真实传感器数据

## 硬件环境

| 项目 | 说明 |
|------|------|
| 开发板 | ST NUCLEO-H563ZI（STM32H563ZI，Cortex-M33） |
| LED | PB0（板载 LD1） |
| 按键 | PC13（板载用户按键，高电平有效） |
| 串口 | USART3（PD8 / PD9），经 ST-Link VCP 虚拟串口输出 |
| CAN（H563） | FDCAN1，PD0=CAN_RX，PD1=CAN_TX |
| CAN（F103 节点） | CAN1（bxCAN），PA11=CAN_RX，PA12=CAN_TX |
| CAN 收发器 | SN65HVD230（3.3V 供电），总线两端各 120Ω 终端电阻 |
| 存储 | 片内 Flash `storage_partition`（偏移 0x1F0000，64 KB） |

F103 节点为 STM32F103C8T6（Blue Pill），标准库裸机工程，无 RTOS。

## 软件环境

- Zephyr RTOS 4.4.99
- Zephyr SDK 1.0.1
- 上位机：Python 3 + pyserial
- F103 节点：Keil MDK + STM32F10x 标准库

## 编译与烧录

```bash
west build -b nucleo_h563zi
west flash
```

## 上位机使用

```bash
pip install pyserial
python3 host.py
```

串口在 `host.py` 顶部配置：Windows 用 `COM10`，Linux 用 `/dev/ttyACM0`。
Linux 首次使用需要串口权限：

```bash
sudo usermod -aG dialout $USER   # 重新登录后生效
```

运行后在 `>` 提示符输入指令，校验通过的数据会追加写入 `sensor_log.csv`。

## 已知限制

- 传感器数据为模拟值（`200 + i % 100` / `400 + i % 100`），尚未接入真实温湿度传感器
- CAN 载荷目前是固定测试图案，尚未把真实传感器数据放进 CAN 帧
- RTC 无电池，掉电后回到默认时间；目前靠「年份合理性检查」判断是否需要重新校准，
  尚无上位机对时指令
- Modbus 从站尚未实现
